# 自動販売機シミュレーター
# Japanese Vending Machine Simulator

## 1. プロジェクト概要

本プロジェクトは、日本の自動販売機を題材にした初心者向けの C 言語プログラムです。
ターミナル上で飲み物を選択し、金額を入力すると、購入結果とお釣りを表示します。

実際の自動販売機のハードウェアを制御するものではなく、C 言語の学習と
ソフトウェアテストの練習を目的としたシミュレーターです。

## 2. 開発目的

- C 言語の基本（変数、条件分岐、ループ、関数、標準入力）を理解する
- 入力値の検証（バリデーション）を学ぶ
- テスト仕様書を作成し、実際にテストを実行する経験を積む
- 日本での就職活動（C 言語テストエンジニア / 組込みソフトウェアエンジニア）に向けたポートフォリオを作成する

## 3. 主な機能

- 3 種類の飲み物と価格のメニュー表示
- メニュー番号による飲み物の選択
- 金額の入力と購入処理
- お釣りの計算と表示
- 不正な飲み物番号の拒否
- 不正な金額の拒否
  - 文字入力
  - 空入力
  - マイナスの金額
  - 0 円
  - 表現できないほど大きい金額（オーバーフロー）
  - 上限（100000 円）を超える金額
- 金額不足の判定と不足額の表示
- `0` を入力すると終了
- 購入後はメニューに戻り、続けて購入できる
- 入力が終了した場合（EOF）も安全に終了する

## 5. 使用技術

- C 言語（1 ファイル構成: `main.c`）
- 標準ライブラリ
  - `stdio.h`（`printf`, `fgets`）
  - `stdlib.h`（`strtol`）
  - `string.h`（`strchr`）
  - `errno.h`（`errno`, `ERANGE`）
- 入力処理
  - `fgets` で 1 行ずつ読み取る
  - `strtol` で整数に変換する
  - `errno` と `ERANGE` でオーバーフローを検出する
- 外部ライブラリは使用していない

## 6. コンパイル方法

GCC が必要です。MinGW などの GCC をインストールし、`gcc` コマンドが使える状態にしてください。

プロジェクトのフォルダで、次のコマンドを実行します。

```powershell
gcc -Wall -Wextra -Wpedantic main.c -o vending_machine.exe
```

- `-Wall` / `-Wextra`: 警告を表示する
- `-Wpedantic`: 標準規格に沿っているか確認する
- `-o vending_machine.exe`: 実行ファイル名を指定する

コンパイルが成功すると、`vending_machine.exe` が作成されます。

## 7. 実行方法

```powershell
.\vending_machine.exe
```

日本語が文字化けする場合は、先に文字コードを UTF-8 に変更してから実行してください。

```powershell
chcp 65001
.\vending_machine.exe
```

実行すると、次のようなメニューが表示されます。

```text
====================================
     自動販売機シミュレーター
     Japanese Vending Machine
====================================

1. Water       - 100 yen
2. Green Tea   - 120 yen
3. Coffee      - 150 yen
0. Exit

Select a drink:
```

飲み物の番号を入力し、続けて金額を入力します。
購入が成功すると、飲み物の名前とお釣りが表示されます。

## 8. テスト内容

テスト仕様書は [docs/test_cases.md](docs/test_cases.md) にまとめています。

主なテスト内容は次のとおりです。

- 正常購入（ちょうどの金額、お釣りあり）
- 不正な飲み物番号
- 文字入力、空入力
- マイナスの金額、0 円
- 金額不足
- 金額のオーバーフロー
- 終了オプション
- 入力終了（EOF）時の安全な終了

2026-10-28 時点で 17 件のテストを実行し、17 件すべてが合格しました。
テストは入力リダイレクトを使用して実行し、終了コード `0` も確認しています。

## 9. 現在の制限事項

- 実際の自動販売機のハードウェアを制御するものではない
- 硬貨・紙幣の物理的な処理は行わない
- 在庫管理は行わない
- お釣りは金額の計算のみで、金種（100 円玉、10 円玉など）の組み合わせは計算しない
- 自動販売機や鉄道に関する業界標準には準拠していない
- 自動テストフレームワーク（CUnit など）は使用していない
- テストは手動テスト（入力リダイレクト）で実施している
- ソースコードは 1 ファイル構成である
